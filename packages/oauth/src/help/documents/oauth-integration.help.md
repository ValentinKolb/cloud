Create one OAuth client per external application and environment. This keeps redirect URLs, access rules, and secret rotation independent.

## Before creating the client {icon="code"}

- Obtain the exact callback and optional logout callback URLs from the external application.
- Decide whether the application can keep a secret. Browser and native clients are public; a protected server-side application can be confidential.
- Decide which users may sign in and which claims the application actually needs.

## Configure the external application {icon="settings"}

:::steps
1. Create the client and copy its client id.
2. Copy the secret immediately for a confidential client; it is not shown again.
3. Prefer the discovery URL when the external application supports OpenID Connect discovery.
4. Otherwise copy the authorization, token, UserInfo, and JWKS endpoints shown on the OAuth page.
5. Request `openid` plus only the optional scopes needed by the application.
6. Test with a user who should have access and one who should not.
:::

## Redirect URLs {icon="point"}

OAuth compares redirect URLs exactly. Scheme, host, port, path, and trailing slash all matter. Register the URL generated by the application rather than a shortened or manually altered version.

:::warning Store client secrets securely
A confidential-client secret grants application credentials. Put it in the external application's secret store, not its source code, browser bundle, screenshots, or documentation.
:::
